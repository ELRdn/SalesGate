# SalesGate Internationalization (i18n)

SalesGate v0.4.1 is a self-hosted OSS product supporting **English (en)** and **Japanese (ja)** with English as the default.

## Supported Locales

| Locale | Code | File | Label |
|--------|------|------|-------|
| English | `en` | `messages/en.json` | English |
| Japanese | `ja` | `messages/ja.json` | 日本語 |

Default: `en` (canonical UI copy). Japanese is first-class.

## URL Strategy

No locale prefix. Routes stay:

```
/ /approvals /leads /tasks /history /suppression /playbooks /settings /account /mcp
```

Locale is independent of URL.

## Locale Resolution

Priority:

1. `salesgate-locale` cookie (`en`/`ja`, 1y)
2. `Setting` `ui.defaultLocale` in SQLite
3. `Accept-Language` header (contains `ja` → `ja`)
4. fallback `en`

No per-user DB preference in v0.4.x; `Setting` is global default and cookie is browser override. Future User model can extend.

## Storage

- Cookie: `salesgate-locale=en|ja` (written on Settings → General → Language and on profile globe toggle)
- Setting keys: `ui.defaultLocale`, `ui.timeZone`, `ui.dateFormat`, `ui.timeFormat` (via `updateSettings`, `STRING_KEYS` + `ui.*` allowlist)

## Translation Structure

```
messages/
  en.json  # canonical
  ja.json
src/i18n/
  config.ts   # SUPPORTED_LOCALES, DEFAULT_LOCALE, LOCALE_COOKIE
  locale.ts   # getLocale(), getLocaleSettings() (server: cookies/headers/Setting)
  format.ts   # formatDate/formatDateOnly/formatRelativeTime/formatNumber (Intl)
  provider.tsx # I18nProvider + useI18n()/useLocale() (client)
```

Keys are semantic:

```
navigation.dashboard
approval.actions.approve
approval.status.awaiting
dashboard.metrics.pendingApprovals
settings.general.language
```

## Date / Time Formatting

Settings → General:

- **Language**: English / 日本語
- **Time zone**: auto / UTC / Asia/Tokyo / America/New_York / Europe/London / Australia/Sydney (Intl-supported, auto → browser/system)
- **Date format**: locale default / YYYY/MM/DD / MM/DD/YYYY / DD/MM/YYYY
- **Time format**: auto / 24-hour / 12-hour

`src/i18n/format.ts` uses `Intl.DateTimeFormat` and `Intl.RelativeTimeFormat`. Domain timestamps are not mutated — only presentation changes.

## Do Not Translate

- Company / person names, emails, user-entered subject/body
- Playbook names, agent names, MCP tool names, API names
- DB IDs, raw URLs, hash values, message IDs

DB enums are mapped at display time: `t('status.approval.'+dbStatus)` etc.

## Adding Strings

1. Add to `messages/en.json` (canonical)
2. Add same key to `messages/ja.json`
3. Use via `const { t } = useI18n()` then `t('key', {param})`
4. Server components: use `createTranslator(locale)` pattern (see `src/app/page.tsx`)

## Adding a Locale

1. Add to `SUPPORTED_LOCALES` in `src/i18n/config.ts`
2. Create `messages/{code}.json`
3. Update `LOCALE_LABELS` and `getLocale()` handling

## Text Length

English is often longer than Japanese. Sidebar labels, pills, table columns, modal headings, and settings nav are tested for wrapping/truncation (see DESIGN.md).

## Testing

- Switch en→ja via Settings → General or Topbar globe → reload persists (cookie + Setting)
- Approval/lead/task status translation from enums
