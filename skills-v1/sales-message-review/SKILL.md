# B2B営業メール送信前チェック（レビュー）

SalesGate で送信予定の B2B営業メールが「スパム扱いされないか・法的リスクがないか・読んで自然か」を、送信前に検証するスキルです。

**最重要のルール：** このスキルは**チェックだけ**を行い、**`submit_draft` を呼びません**。提出（承認キューへの登録）は `sales-email-copy` の作成フロー側が担当します。レビュー結果は判定結果（PASS / NEEDS_FIX / REJECT）と修正提案として返す。

---

## 1. チェック項目（スコアリング付き）

チェックは次の7項目を、それぞれ**0〜10点**で評価する（10が最も良い）。合計を10項目で割らず、**重み付きで総合点（0〜100）** を算出する。

| # | チェック項目 | チェックする内容 | 重み |
|---|---|---|---|
| 1 | スパムワード検出 | 「無料」「今すぐ」「限定」等の過剰使用、全大文字、過剰な感嘆符（!!!・???）、不自然な記号多用 | 15% |
| 2 | 虚偽・過剰な約束 | 「絶対に」「確実に」「保証します」「必ず成果」等の根拠のない確約表現 | 15% |
| 3 | 個人情報・機密情報の混入 | 他社名・社内情報・別リードの情報・個人の電話番号・住所・メールアドレス等の混入 | 20% |
| 4 | **CTA単一性（v1新設）** | **行動を促す文が本文中に1つだけか。副次的誘因（「事例もご用意」「資料をお送りします」等）によるCTA分散がないか。1メール=1CTAの原則** | 15% |
| 5 | **CTAのハードル（v1新設）** | **CTAの行動が相手にとって負担が低いか（「現状の確認のみでも構いません」=低ハードル / 「ぜひご検討ください」=高ハードル）。時間の明示があるか** | 10% |
| 6 | トーン（上から目線・命令調・AI臭） | 相手を見下す言い回し、命令調（「してください」の乱用）、機械翻訳・LLM定型句のAI臭、定型敬語の連発（「ご多忙の折」「ご検討のほど」等） | 10% |
| 7 | 文字数（v1強化） | 初回接触は**日本語250字前後**（300字超は冗長警告・160字未満は情報不足）。全般で必要最小限か | 10% |
| 8 | 件名・宛先の整合 | 具体性があるか・30文字以内か・抽象語でないか。会社名・担当者名の表記ゆれ・誤字がないか | 5% |

## 2. レビュー手順

以下の順番で進める。機械的チェックを先に、文脈チェックを後に行う。

### ① 機械的チェック（禁止語リスト）
文面に対してマクロ的な検出を行う。以下を探す。

**スパム的表現（要項目1）：**
- 「無料」「今すぐ」「限定」「期間中」「最後のチャンス」「購入」「ご登録はこちら」等の販促語の過剰使用
- 全大文字（日本語は該当しにくいが、英語部分での `FREE`・`ACT NOW`）
- 感嘆符・疑問符の連打（`!!!`・`???`）、顔文字・絵文字
    
**誇張表現（要項目2）：**
- 「絶対に」「確実に」「保証します」「100%」「最強」「唯一無二」「劇的に」
- 数字の根拠がないままの効果主張（「成果◯倍」など）

**情報混入（要項目3）：**
- 本文に他の会社名・他リードの担当者名
- 社内の機密用語・内部資料名・内部の人物名・内線番号
- 個人の電話番号・住所・生年月日などの個人情報

### ② 文脈チェック（natural-japanese / meiseki の観点 + v1追加項目）
機械では拾えない「読んで自然か」を確認する。

- **`natural-japanese` の観点：** AI臭さ（「〜することが可能です」「ご検討のほどお願い申し上げます」等の定型リズム、過剰な敬語、単調な文末の連続）がないか。定型敬語の連発（「ご多忙の折」「ご検討のほど」「〜していただけると幸いです」）を検出。
- **`meiseki` の観点：** 一読で意味が取れるか。一文が長すぎないか、二重否定・過剰な名詞化・LLM定型句（「重要なのは〜」「掘り下げると〜」）がないか。
- **CTA単一性チェック（v1）：** 本文中に「行動を促す文」を列挙し、1つだけであるか確認。以下のパターンを検出：
  - 「ご検討ください」「お返事ください」「お越しください」等の直接的CTA
  - 「事例もご用意しています」「資料をお送りします」等の**副次的誘因**（CTAを別行動へ拡散させる）
  - 「ご都合のよい日時があれば」「もし興味があれば」等の条件付きCTA
  - **副次的誘因は本文から外し、相談後の返信で渡すよう指摘する。**
- **文字数チェック（v1）：** 日本語本文の実測文字数を報告。初回接触は250字前後（300字超は冗長警告・160字未満は情報不足）。
- **CTAハードルチェック（v1）：** CTAの行動が相手にとって負担が低いか確認。高ハードルCTA（「ぜひご検討ください」「ご返答いただけますと幸いです」）は低ハードル（「現状の確認のみでも構いません」「15分ほどお話しする機会を」）に書き換えるよう指摘。

必要に応じて、2つのスキル本体を適用して該当箇所を洗い出す。

### ③ スコアリング
各7項目を0〜10点で採点し、重み付きで総合点（0〜100）を出す。採点は理由を添える。

### ④ 修正提案
各低得点項目に対し、**具体的な代替文**を提示する（「直してください」ではなく、置き換え候補の文言を実際に示す）。
例：
- スパム語 `今すぐお申し込みください` → `ご都合のよい日時をお知らせください`
- 誇張 `貴社の売上は確実に上がります` → `導入企業では平均◯％の改善事例があります`
- AI臭 `〜させていただきたく存じます` → `〜いただけますと幸いです`

### ⑤ 提出可否の判定
総合点に応じて判定を下す。

| 総合点 | 判定 | 意味 |
|---|---|---|
| 80〜100 | `PASS` | そのまま提出してよい |
| 60〜79 | `NEEDS_FIX` | 低得点項目を修正（修正案付き）してから提出 |
| 0〜59 | `REJECT` | スパム・虚偽・情報漏えいリスクが高く、送信すべきでない |

**注：** 項目3（個人情報・機密情報の混入）は、10点満点中5点未満の場合、総合点にかかわらず**`REJECT`** を優先する（法令・社内規程リスクは甘く見ない）。項目2（虚偽・過剰な約束）も同様に5点未満なら `REJECT` を検討する。

## 3. 出力形式

レビュー結果は以下のJSON形式で返す。

```json
{
  "verdict": "PASS | NEEDS_FIX | REJECT",
  "totalScore": 85,
  "charCount": 220,
  "scores": [
    { "item": "スパムワード検出", "score": 9, "reason": "販促語は1回のみ、強調記号なし" },
    { "item": "虚偽・過剰な約束", "score": 10, "reason": "確約表現なし" },
    { "item": "個人情報・機密情報の混入", "score": 10, "reason": "混入なし" },
    { "item": "CTA単一性", "score": 9, "reason": "行動を促す文は1つのみ。副次的誘因なし" },
    { "item": "CTAのハードル", "score": 9, "reason": "低ハードル。時間明示あり" },
    { "item": "トーン", "score": 8, "reason": "全体的に自然。1箇所だけ定型敬語が見える" },
    { "item": "文字数", "score": 9, "reason": "220字で250字前後に適合" },
    { "item": "件名・宛先の整合", "score": 7, "reason": "具体的だが「ご提案のご案内」で少し抽象的" }
  ],
  "issues": [
    { "severity": "warning", "item": "トーン", "detail": "『〜させていただきたく存じます』がAI臭", "suggestion": "『〜いただけますと幸いです』" },
    { "severity": "info", "item": "件名", "detail": "『ご提案のご案内』は抽象語", "suggestion": "『〇〇社の採用業務について、1点共有させてください』" }
  ],
  "fixed": {}
}
```

- `verdict` が `PASS` の場合は `issues` と `fixed` は空でよい。
- `verdict` が `NEEDS_FIX` または `REJECT` の場合、`fixed` に **修正後の subject / body** を含める。修正後はスコアリングを再実行し、最終判定を付記する。

```json
{
  "verdict": "NEEDS_FIX",
  "totalScore": 72,
  "scores": [ "…上記と同型…" ],
  "issues": [ "…修正候補の列挙…" ],
  "fixed": {
    "subject": "（修正後の件名）",
    "body": "（修正後の本文）"
  }
}
```

## 4. 禁止事項

1. **`submit_draft` を呼ばない：** このスキルはレビュー専用。文面の提出（承認キューへの登録）は `sales-email-copy` のフロー側が行う。レビュー結果はそのまま返す。
2. **実際の送信・送信準備をしない：** メール送信ツールを直接呼んだり、送信予約を組んだりしない。
3. **無根拠にPASSを出さない：** 明らかなスパム語・誇張表現・情報混入があるのに合格判定を出さない。`REJECT` 判定が必要な場合は躊躇しない。
4. **レビューを無期限に繰り返さない：** 修正提案を出すだけで終わらず、修正後の最終判定まで付ける。
5. **本文を書き換えて一方的に確定させない：** 修正案は「提案」として返し、勝手に新しい文面を確定・提出するのは避ける。新規作成が必要な場合は `sales-email-copy` を参照させる。
6. **CTA単一性の指摘を無視しない（v1）：** 副次的誘因によるCTA分散を検出した場合、必ず指摘し、修正案を含める。「事例もご用意」等は本文から外して相談後の提供に回すよう具体的に示す。
7. **文字数チェックを怠らない（v1）：** 300字超の文面に冗長警告を出さない場合や、250字前後の目安を無視してPASSを出さない。
