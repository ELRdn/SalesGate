# B2B営業メール文面作成ガイド（SalesGate）

SalesGate の承認ファーストのフローに沿って、B2B営業メールの文面（件名・本文）を設計し、`submit_draft` に渡すためのスキルです。

**最重要のルール：** エージェントはメール文面を作るだけで、**実際の送信は行いません**。作成した文面は必ず `submit_draft` で承認キューに提出し、人間の承認を経て初めて送信されます。AIが勝手に送信モジュールやメール送信ツールを直接呼んで実在の相手へ送ることは、どんな状況でも絶対に避けてください。

---

## 1. 作成フロー

営業メールは以下の順番で作ります。手順を飛ばさず、①から⑤まで必ず通ること。

### ① リード情報の確認
文面を書く前に、対象リードの情報を確認する。

- `search_leads`（query・status・limit）を使って、会社名・担当者名・メールアドレスが正確に揃っているか確認する。
- 確認すべき項目：**会社名 / 担当者名（名前の表記ゆれ）/ 業種 / 規模 / 過去のやりとり履歴 / 現在のステータス（ACTIVE・RESPONDED・SLEEPING・SUPPRESSED）**。
- ステータスが `SUPPRESSED` のリードには送信提案を出さない（抑制リスト扱い）。
- 情報が不足している場合、あてずっぽうで埋めず、「このリードをどう呼びたいか」を決めるのに必要な最低限（少なくとも会社名と担当者名）を確保する。

### ② 目的の明確化
このメールで「何を達成するか」を一文で明確にする。例：

- 説明会 / デモの予約を取る
- 資料ダウンロードやWebサイト訪問などの小さな一歩を踏ませる
- 質問に答えて関係を前進させる
- 休眠リードに再度興味を持ってもらう

目的が曖昧だと本文も曖昧になる。**1通につき目的は1つだけ**に絞る。

### ③ 文面設計
件名 → 冒頭 → 価値提案 → CTA → 署名 の順で組み立てる（詳細は「2. シチュエーション別ガイド」参照）。

### ④ 仕上げ
書き上げた文面をそのまま提出しない。以下の仕上げ工程を必ず適用する。

1. **`natural-japanese` スキル**を適用 — AI臭さ（「〜することが可能です」「お世話になっておりますが」「ご検討のほどお願い申し上げます」等の定型リズム）を除去し、仕事の日本語として自然にする。
2. **`meiseki` スキル**を適用 — 一読で意味が取れる状態にする。一文が長い、二重否定、過剰な名詞化、「重要なのは〜」等のLLM定型句を削ぐ。

仕上げは「より丁寧に」ではなく「より明確に・より人間らしく」が目的。言葉を増やさず削る方向で調整する。

### ⑤ `submit_draft` で提出
完成した文面を `submit_draft` で承認キューに提出する（submit_draft は送信ではなく承認キューへの提出である点を再確認）。

## 2. シチュエーション別ガイド

### 2-1. 初回接触（cold email）

**ねらい：** まだ会ったことも知らない相手に、読んでもらい、小さな一歩を踏んでもらう。

- **件名は具体的に：** 「ご提案」や「お問い合わせ」のような抽象語は避ける。会社名・相手の関心・価値が1行で分かる件名にする（30文字以内目安）。
  - 良い例：`〇〇社の採用業務について、1点共有させてください` / `御社のデモの話を考えてみました`
  - 悪い例：`お世話になります` / `お願いがあります` / `ご提案のご案内`
- **個別観察からの導入（v1）：** 冒頭1文で相手の具体的状況に触れる。「御社のサイトを拝見し、◯◯を強みとされているのを拝見しました」のように、公開情報から観察を述べる。決めつけにならないよう「〜のではとお見受けしました」「〜かもしれません」の条件付き表現を併用する。
  - 良い例：「御社のサイトで、金属加工・試作部品の短納期対応が強みと拝見しました。短納期を支える進捗管理に手間をかけていらっしゃるのではとお見受けしました」
  - 悪い例：「御社は生産管理が屬人的で問題でしょう」（決めつけ）
- **1文で価値提案：** 冒頭の数行で「なぜ読む価値があるか」を具体的に言う。自社の製品説明ではなく「相手の問題・興味」に言及する。具体の改善対象を挙げる（工数入力・納期回答時間・進捗・実績の集計など）。
- **短く（圧縮指針v1）：** 初回接触は**日本語250字前後**（冗長警告: 300字超）。段落3つ程度（導入 → 価値 → CTA）。削ってよい冗長敬語：「ご多忙の折とは存じますが」「ご検討のほどよろしくお願いいたします」「突然のご連絡で失礼いたします」等。
- **リンクは最小限：** 1つまでにする。初回で資料を2つも3つも貼ると読む気を削ぐ。
- **CTAは1つ（抵抗最小化v1）：** 行動を促す文は**1メールにつき1つだけ**。副次的誘因（「事例もご用意しています」「資料をお送りします」等）は本文に入れず、相談後の返信で渡す。
  - 低ハードルCTA推奨：「15分ほど現状の確認を兼ねてお話しする機会をいただけないでしょうか。現状のお困りごとの確認のみでも構いません。」
  - 高ハードル（避ける）：「ぜひご検討ください」「ご返答いただけますと幸いです」
- **押し売りしないトーン：** 「ぜひ御社の◯◯を導入ください」ではなく、相手の判断を委ねる表現を心がける。

### 2-2. 無返信フォローアップ

**ねらい：** 届いたか分からない相手へのリマインド。しつこくならず、新情報を1つ足す。

- **回数上限：** 送信は2〜3回まで。それ以上は打ち切る判断をする（タスクとして確認する）。
- **前回のメールを想起させる：** 「先日お送りした◯◯の件」と具体的に触れ、同じ文面をそのまま再送しない。
- **新情報を1つ追加：** 前回と違う角度のメリット・事例・期間限定の事実を1つだけ加える。何もないなら「返信不要です」と潔く締める方が自然。
- **押しつけがましくないトーン：** 「まだご覧になっていないようでしたら」のように、相手の都合を気遣う言い回しを挟む。
- フォローアップのたびに件名の冒頭に番号や「1回目」「再送」のような表記を入れて、連続していることが分かるようにする（例：`【再送】◯◯の件`）。

### 2-3. 返信対応

**ねらい：** 相手から来た反応（質問・興味・相談）に、誠実かつ先へ進む形で答える。

- **質問に先に答える：** 相手の問いには冒頭で直接・明確に答える。前置きを長くしない。
- **議題を1つに絞る：** 相手の質問が複数あっても、このメールで前に進めたい論点は1つにする。
- **次のアクションを明示：** こちらが次にやること、相手に期待することを具体的に書いて、次の一手を決める（例：「では候補日をご3つまでお知らせください」「コメントを添えてご返送ください」）。
- 相手の話を踏まえた内容にし、テンプレートをそのまま貼り付けたような返信は避ける。

### 2-4. 休眠リード再活性化

**ねらい：** 長く連絡が途絶えた相手に、興味を再点火しつつ、無理を強要しない。

- **軽いタッチで：** 重い契約話から入らず、価値の再提示から入る。導入で改めて簡単に自己紹介（名乗り直し）をしてもよい。
- **価値の再提示：** 前回関心を持った領域に関連する、新しい事例・機能・知見を1つ提示する。
- **「返信不要」の選択肢を与える：** 「もしご興味がなければ、このまま放置くださって結構です」のように、返信しない自由を明示して心理的負担を下げる。
- 再活性化は最初の1通だけで判断せず、状況に応じて回数を管理する（2回まで目安）。

### 2-5. 初回接触テンプレート（v1追加）

以下の構成を参考に文面を組み立てる（約230字・ワンパラグラフ）。

```
（会社名 御中）

（役職）（担当者名）様

（名乗り）。（個別観察：サイト拝見からの具体的な状況言及）。

（価値提案：中小企業向け・導入期間・初期費用・段階的導入の1点）。

（CTA：15分ほど現状の確認を兼ねてお話しする機会をいただけないでしょうか。確認だけでも構いません。）

よろしくお願いいたします。
```

### 2-6. 失敗例と回避策（v1追加）

| 失敗パターン | 具体例 | 回避策 |
|---|---|---|
| 冗長な敬語の定型を重ねる | 「ご多忙の折とは存じますが」「ご検討のほどよろしくお願いいたします」等の連打 | 250字前後に圧縮し、定型は1つまで |
| CTAが2つ以上に分裂する | 「ご検討ください」「資料をお送りします」「ご連絡ください」が並ぶ | 1メール=1CTAの原則。副次的誘因は本文から外す |
| 相手の状況を決めつける | 「御社は生産管理が屬人的で問題でしょう」 | 条件付き表現（「〜かもしれません」「〜のではとお見受けしました」）を併用 |
| 抽象的な件名 | 「ご提案のご案内」「お願いがあります」 | 会社名・相手の関心・価値を1行で具体的に |
| 具体の改善対象がない | 「DXを進めましょう」等の一般論 | 工数入力・納期回答時間・進捗集計等を挙げる |

## 3. 日本語B2Bメールのトーンガイド

B2B営業メールの文面は以下のトーンを基本とする。

- **です・ます調**を一貫して使う。「である調」と混在させない。
- **簡潔さ・1文1意：** 一文に主張は1つ。読点だらけの長文・従属節の入れ子を避ける。
- **敬意と距離感：** 相手の会社・業界を敬う。ただし過剰な謙譲（「〜させていただきたく存じます」の連発）はAI臭・文書臭のもとになるため、自然な敬意に留める。
- **絵文字は使用禁止：** ✨😀📞など、ビジネスメール本文には一切入れない。
- **過剰な強調は禁止：** 「！！！」「？？？」「☆☆☆」のような記号連打や、全角英数字の乱用は避ける。
- **受け身・冗長表現を避く：** 「〜となっております」「〜になっております」を濫用しない。能動的で短い文を好む。
- 挨拶文は控えめに： 頭語（「拝啓」）や結語（「敬具」）は必須ではない。日本のB2Bでは「〇〇株式会社　△△様」から本文に入る簡潔な形が増えている。

## 4. 品質チェックリスト（提出前）

`submit_draft` に出す前に、以下の項目を必ず確認する。

- [ ] **宛先名が正確か**（会社名・担当者名に表記ゆれ・誤字がないか。別の会社名になっていないか）
- [ ] **約束事や虚偽の主張がないか**（「絶対に成果が出ます」「確実に」等の過剰な約束。「保証」に類する表現）
- [ ] **件名が具体的か**（抽象語でなく、相手にとって意味のある一文になっているか。30文字以内目安）
- [ ] **個別観察から始めているか（v1）**（初回接触ではサイト拝見等の具体的観察1文で始まっているか。決めつけになっていないか）
- [ ] **長すぎないか（v1強化）**（初回接触は**日本語250字前後**。300字超は冗長警告）
- [ ] **個人情報・機密情報が混ざっていないか**（他の顧客名・社内情報・個人の電話番号など）
- [ ] **CTAが1つに絞られているか（v1強化）**（行動を促す文が本文中に1つだけ。副次的誘因「事例もご用意」等がないか）
- [ ] **CTAのハードルは低いか（v1追加）**（「現状の確認のみでも構いません」等の低ハードル。高ハードル「ぜひご検討」を避ける）
- [ ] **`natural-japanese` と `meiseki` で仕上げたか**（AI臭と読解負荷を除去したか）

## 5. 出力形式

完成した文面は、以下のJSONの形で組み立て、`submit_draft` の各パラメータに渡す。

| フィールド | 説明 | 必須 |
|---|---|---|
| `subject` | メールの件名（具体的に、30文字以内目安） | 必須 |
| `body` | メールの本文（日本語・ですます調・CTA1つ） | 必須 |
| `leadId` | 対象リードのID（`search_leads` で取得） | 提出時には必須 |
| `agentName` | 提出するエージェント名（監査用） | 提出時には必須 |
| `evidence` | このリードに送る根拠（調査メモ：会社の情報・なぜ今・何を提案するか） | 推奨 |
| `riskFlags` | リスクフラグ（例：`["抑制リスト該当"]` `["過去に返信あり"]` `["休眠3ヶ月以上"]`） | 任意 |

```json
{
  "subject": "〇〇社の採用業務について、1点共有させてください",
  "body": "〇〇株式会社 御中\n\n△△様\n\n◯◯部の添田と申します。\n\n御社の採用業務がDX化の検討段階とのこと、ご担当の△△様にご相談の機会をいただければ幸いです。\n弊社の×サービスは、採用フローの工数削減をサポートしており、同業他社の導入実績で平均◯時間を短縮しています。\n\nもしご興味があれば、15分程度のデモで具体的な事例をご紹介させてください。ご都合のよろしい日時をお知らせいただけますと幸いです。\n\nよろしくお願いいたします。",
  "evidence": "SaaS業界の採用DX化が進む中、御社HPで採用業務の負荷に関する記述を確認。search_leadsでACTIVEステータスを確認済み。",
  "riskFlags": []
}
```

文面を完成させたら、このJSONを `submit_draft` に渡して承認キューへ提出する。

## 6. 禁止事項

1. **実在する送信をしない：** エージェントがメール送信ツールを直接呼んで、未承認のまま実際の相手に送ることを絶対にしない。`submit_draft` は**承認キューの提出**であり、送信ではない。送信は人間が承認した後にのみ行う。
2. **文面に虚偽・未確認の情報を含めない：** 未確認の導入実績・数値・保証は書かない。
3. **個人情報・機密情報、他社名を本文に入れない：** 別のリードの情報・社内の機密・他の顧客名を混入させない。
4. **過剰な宣伝文句・誇張表現を使わない：** 「最強」「唯一無二」「即効性」等の根拠のない表現を避ける。
5. **レビューのみの依頼には本スキルでなく `sales-message-review` を使う：** このスキルは文面の**作成**を担当する。既存文面の検証・修正提案はレビュースキルに委ねる。

文面ができたら `submit_draft` で承認キューに進める。人間の承認を待ち、承認後に行われる送信はその後のプロセスで処理される。
