# 営業文作成スキル 比較テストレポート（v0 vs v1）

- **実施日**: 2026-08-16
- **対象スキル**: `sales-email-copy` / `sales-message-review`
- **目的**: スキル無し・スキル有り（v0）・改善版（v1）で生成したコールドメールの品質を比較し、スキルの効果と改善の妥当性を検証する

## 1. テスト方法

### シナリオ（同一条件）

仮想クライアント「株式会社アルファ製作所（金属加工・試作部品メーカー・従業員80名）製造部長 佐藤太郎様」宛の初回接触メールを、製造業向けDXコンサル（生産管理システム導入支援・導入3ヶ月・初期費用抑制）のシナリオで生成。

| パターン | 内容 |
|---|---|
| A | スキルなし（素のプロンプト・ベースライン） |
| B | `sales-email-copy` のみ（スキルに従って作成） |
| C | 素で作成 → `sales-message-review` でレビュー・修正 |
| D | `sales-email-copy` で作成 → `sales-message-review` でレビュー → natural-japanese / meiseki で仕上げ |

- 各パターンをサブエージェント（新規セッション）で実行
- 生成文面は**ブラインド評価**（どの文面がどのパターンか伏せて第三者サブエージェントが採点）
- 採点基準: 8項目×10点満点（件名・スパム感・虚偽/過剰約束・トーンの自然さ・相手への配慮・価値提案・CTA・長さ）＝80点満点

## 2. 第1ラウンド（v0のみ・4文面評価）

| パターン | 合計 | 順位 |
|---|---|---|
| C（reviewのみ） | 66 | 1位 |
| B（email-copyのみ） | 64 | 2位 |
| D（両方） | 60 | 3位 |
| A（スキルなし） | 52 | 4位 |

**主な気づき**:
- スキル使用（B/C/D）がスキルなし（A）を全パターン上回った
- 1位Cの要因: 「現状の確認のみでも構いません」という抵抗最小化CTA、業界業務への具体的言及、箇条書き圧縮
- D（両方）が3位だった要因: 「導入事例もご用意しています」がCTAを別行動へ拡散（副次的誘因）

## 3. v1（改善版）の作成

上記の気づきを反映して v1 を作成:

| スキル | v1の主な改善 |
|---|---|
| `sales-email-copy` | 個別観察からの導入（サイト拝見・条件付き表現）を新設 / 抵抗最小化CTA設計 / 本文250字前後への圧縮指針 / 具体の改善対象（工数入力・納期回答・進捗集計）の例 |
| `sales-message-review` | チェック項目を7→8に拡張（**CTA単一性**・CTAハードルを新設）/ 文字数チェック（250字前後・300字超は冗長警告）/ AI臭検出の強化 |

## 4. 第2ラウンド（v0 + v1・7文面ブラインド評価）

| 文面 | 正体 | 合計 | 順位 |
|---|---|---|---|
| B（v0 email-copy） | v0 | 69 | 1位 |
| B'（v1 email-copy） | v1 | 65 | 2位 |
| D'（v1 両方） | v1 | 65 | 3位 |
| C（v0 review） | v0 | 64 | 4位 |
| D（v0 両方） | v0 | 64 | 5位 |
| A（スキルなし） | — | 55 | 6位 |
| C'（v1 review） | v1 | 51 | 7位 |

### v0 vs v1 比較

| パターン | v0 | v1 | 差分 |
|---|---|---|---|
| email-copy | 69（1位） | 65（2位） | -4 |
| review | 64（4位） | 51（7位） | -13 |
| 両方 | 64（5位） | 65（3位） | +1 |

## 5. 考察

1. **スキルの効果は明確**: スキル使用がベースライン（スキルなし）を概ね上回った
2. **v1の改善が文面の質に確実に効いたとは言えない**: 差分は生成のばらつき・評価者バイアス（±5点程度）の範囲
3. **スキルの自己採点は甘い**: C'はスキル内で93.5点PASS判定だったが、ブラインドでは51点（件名32字超・強みの誤読を検出できていなかった）。自己採点は「参考値」と割り切る
4. **生成品質のばらつきが大きい**: 同じスキルでも実行ごとに文面の質がブレる。スキルは「質の高い初稿を作る指針」であり、完璧な出力を保証するものではない

## 6. 決定事項

- **v1を本採用**（`skills-v1/` に配置。指針としては明確に改善されている）
- 過過剰なチューニングはしない（自己採点の甘さは「参考値」と割り切る）
- 最終的な品質は **SalesGateの承認キュー（人間の承認）で担保**する（承認ファースト設計思想）
- 評価用の生テキスト: `mail_A.txt`〜`mail_D.txt`（ワークスペースルート）

## 7. 残課題（記録のみ・対応予定なし）

- スキル自己採点と第三者評価の乖離（チェック項目の厳格化は過剰チューニングになるため見送り）
- CTA単一性チェックなど新項目の検出精度は実運用で確認
